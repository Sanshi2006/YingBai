# 移动端智能客服底座 MVP 说明

## 1. 定位与范围

本项目是一套面向纺织品、鞋类和消费品检测场景的移动端智能客服 MVP。它覆盖知识文档入库、RAG 问答、引用、防幻觉、多轮会话、角色权限、LIMS 订单 Mock、移动端 H5 和对话日志闭环。

当前系统用于本地开发和真机演示，不是生产级客服、身份认证或真实 LIMS 系统。

## 2. 系统架构

```text
手机浏览器 / 微信内置浏览器
          │ 同源 HTTP
          ▼
     Gin 路由与 Handler
      ├─ 文档管理服务 ── PostgreSQL + pgvector
      ├─ Chat 编排服务
      │    ├─ Mock LIMS（只读固定数据）
      │    └─ RAG 服务
      │         ├─ Chat LLM：问题改写、知识回答
      │         ├─ Embedding Provider：查询向量
      │         └─ pgvector：权限过滤后的 Top-K
      └─ 会话日志与最近 5 轮 ── SQLite
```

主要目录职责：

- `mobile/`：原生 HTML、CSS、JavaScript 移动端页面；
- `backend/cmd/server/`：服务启动、配置和依赖组装；
- `backend/internal/handler/`：HTTP 请求校验和稳定响应；
- `backend/internal/service/`：文档、RAG、会话编排和 Mock LIMS；
- `backend/internal/repository/`：PostgreSQL/pgvector 与 SQLite 数据访问；
- `backend/internal/llm/`：厂商无关的 OpenAI Compatible Provider；
- `docs/`：约束、底座说明和测试用例。

## 3. 核心流程与数据流

### 3.1 知识入库

1. 管理页上传 PDF、TXT 或 MD，并填写品类、类型和权限。
2. 后端校验格式、大小、元数据和 SHA-256 内容重复。
3. 提取文本并按标题、段落、句末标点等语义边界切片。
4. 使用 Embedding Provider 分批生成 1024 维向量。
5. 在同一 PostgreSQL 事务中保存元数据、分块、向量和成功状态。
6. 失败时保留原文件、失败状态和安全错误原因，供管理页重试。

### 3.2 RAG 问答

```text
输入校验 → 读取同角色最近 5 轮 → 问题改写 → 查询向量
→ SQL 权限过滤 → Top-K → 相似度阈值 → Grounded Prompt
→ Chat LLM 回答 → 引用返回 → SQLite 日志
```

历史只用于理解代词、省略和连续追问，不能替代本轮授权知识作为事实依据。客户、客服和管理员的历史按角色隔离。

### 3.3 LIMS Mock 查单

Chat 编排服务先识别自然语言中的 `ORD...` 订单号。命中订单意图后直接查询本地只读 Mock，不执行向量检索或大模型调用。

- 固定有效订单：`ORD2026001`；
- 返回：订单号、订单状态、检测进度、报告状态；
- 不存在订单：返回 `found=false`，不生成虚假业务字段；
- 当前不连接、不修改、不删除任何真实 LIMS 数据。

## 4. 接口列表

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/health` | 服务健康检查 |
| POST | `/chat` | RAG 问答、多轮、拒答和 Mock 查单统一入口 |
| POST | `/api/v1/documents` | 上传并处理 PDF/TXT/MD |
| GET | `/api/v1/documents` | 文档分页、搜索和元数据筛选 |
| DELETE | `/api/v1/documents/:id` | 删除原始文件、元数据和分块 |
| POST | `/api/v1/documents/:id/retry` | 重试失败文档 |
| POST | `/api/v1/documents/:id/revectorize` | 事务化重新向量化成功文档 |
| GET | `/` | 移动端聊天页面 |
| GET | `/documents` | 文档管理页面 |

`POST /chat` 的回答类型包括：

- `knowledge`：知识库命中，带引用；
- `refusal`：无足够知识依据，固定转人工文案；
- `order`：Mock LIMS 查询，按情况携带结构化 `order`。

## 5. RAG 与拒答策略

- 默认 Top-K 为 5，可通过 `RAG_TOP_K` 配置为 1～20。
- 默认相似度阈值为 0.55，可通过 `RAG_SIMILARITY_THRESHOLD` 配置为 0～1。
- 只有状态为 `vectorized`、向量模型一致且当前角色有权访问的分块参与排序。
- 回答 Prompt 只包含通过阈值的授权知识片段，并将片段明确标记为不可信数据而不是指令。
- 无结果或结果全部低于阈值时直接返回“知识库暂无依据，请转人工”，不调用最终回答模型。
- 模型、数据库或日志失败均返回稳定错误码，不伪装成成功答案。

## 6. 权限边界

| 角色 | 可检索知识 | 说明 |
| --- | --- | --- |
| 外部客户 `customer` | 公开 | SQL 排序和 LIMIT 前过滤，不会读取内部分块 |
| 客服 `service` | 公开、内部 | 演示级内部角色 |
| 管理员 `admin` | 公开、内部 | 演示级管理员角色 |

角色选择只是演示入口，不是账号登录、组织权限或生产级 RBAC。权限过滤由后端强制执行，隐藏前端按钮不作为授权措施。

## 7. 数据与外部传输边界

- PostgreSQL/pgvector：文档元数据、文本分块和向量；
- SQLite：问题、答案、角色、引用文件名、回答类型、时间和 Session；
- 文件系统：原始上传文件；
- Embedding 服务：上传文档分块和查询文本会发送至 `LLM_BASE_URL`；
- Chat LLM：用户问题、同角色最近 5 轮和本轮授权知识片段会发送至 `LLM_CHAT_BASE_URL`；
- 日志不保存 API Key、完整 Prompt 或完整知识片段。

部署者必须确认内部知识和会话历史发送至外部模型服务符合实际数据安全要求。

## 8. 移动端体验

- 优先适配 375～430 CSS 像素竖屏；
- `visualViewport` 同步实际可视高度，软键盘打开时收起快捷区并滚动到最新消息；
- 首次进入显示明确空状态；
- 请求期间显示“正在查询，请稍候”，并阻止重复提交；
- 网络或接口失败时显示原因和“重新发送”；
- 答案引用可折叠，订单使用结构化卡片；
- Session 保存在 localStorage，刷新后继续使用同一会话。

## 9. 启动与验收入口

完整环境配置、启动、构建、测试、同网段手机访问和故障排查以仓库根目录 `README.md` 为准。正式验收按以下顺序：

1. `docker compose up -d --wait postgres`；
2. 在 `backend/` 执行 `go run ./cmd/server`；
3. 执行 `go test -count=1 ./...`、`go vet ./...` 和 `go build ./cmd/server`；
4. 按 `docs/测试用例.md` 执行自动化及真机用例；
5. 对照 `docs/CONSTRAINTS.md` 的周五验收门禁留存证据。

## 10. 已知限制

- 身份为演示级选择，无法替代生产登录认证和订单归属校验。
- LIMS 为固定只读 Mock，只有 `ORD2026001` 是有效订单。
- PDF 只提取文本层，不支持扫描件 OCR。
- 向量固定为 1024 维，更换模型维度需要数据库迁移。
- 页面刷新后能恢复后端上下文，但不会重新绘制刷新前的消息气泡。
- 文档管理页没有审批、版本对比和组织级权限。
- 当前未实现生产级限流、监控告警、审计后台、高可用和正式安全认证。
- 真机软键盘、微信内置浏览器和局域网防火墙仍需在实际设备环境验收。

## 11. 后续迭代建议

1. 接入正式身份认证、租户和订单归属授权。
2. 用受控 LIMS 只读网关替换 Mock，并增加超时、熔断和审计。
3. 增加会话历史查询接口和刷新后的消息恢复。
4. 增加 OCR、文档版本、审批和批量管理。
5. 建立 RAG 离线评测集、召回率/拒答率指标和 Prompt 回归。
6. 增加限流、敏感信息脱敏、监控告警和生产部署方案。
