版本：1.0  
日期：2026-09-25  
范围：周五验收所需的接口、知识库、权限、多轮、查单、日志和移动端体验。

## 执行约定

- 自动化回归：在 `backend/` 执行 `go test -count=1 ./...`。
- PostgreSQL 集成回归：设置 `TEST_DATABASE_URL` 后执行 `go test -count=1 -tags=integration ./internal/repository`。
- 人工移动端用例：电脑与手机连接同一局域网，按 README 启动服务并使用 375～430 CSS 像素宽度的手机浏览器执行。
- 固定有效 Mock 订单：`ORD2026001`；固定不存在订单：`ORD9999999`。
- “自动化通过”表示对应测试已在 2026-09-25 全量回归中通过；真机项目必须在验收设备上补记结果。

| --- | --- | --- | --- | --- | --- |
| TC-01 | 健康检查 | 后端可启动 | 请求 `GET /health` | HTTP 200，返回 `status=ok` 和稳定服务名 | 自动化通过：`router.TestHealth` |
| TC-02 | 上传支持格式 | PostgreSQL 可用；准备 PDF/TXT/MD | 分别上传三种文件并填写品类、类型、权限 | 三种格式均完成提取、切片、向量化并返回 `vectorized` | 自动化通过：`router.TestDocumentUploadAcceptsAllowedFormats` |
| TC-03 | 拒绝非法上传 | 准备 DOCX 或其他非法格式 | 上传非法文件 | HTTP 415，错误码 `UNSUPPORTED_FILE_TYPE`，文件不落盘 | 自动化通过：`router.TestDocumentUploadRejectsUnsupportedFormat` |
| TC-04 | 文档列表分页筛选 | 已存在多种元数据文档 | 组合文件名、品类、类型、权限、状态和分页参数查询 | 只返回匹配项，分页统计正确；非法参数返回稳定错误 | 自动化通过：`router.TestDocumentListSupportsPaginationAndFilters` |
| TC-05 | 知识命中和引用 | 已有公开知识分块 | 以客户角色发送可命中问题 | 返回 `knowledge`，答案非空，引用包含正确文件名和来源编号 | 自动化通过：`router.TestChatReturnsKnowledgeAnswerWithCitations` |
| TC-06 | 无依据拒答 | 无相关知识或相似度低于阈值 | 发送知识库无关问题 | 固定回复“知识库暂无依据，请转人工”，引用为空，最终回答模型不被调用 | 自动化通过：`router.TestChatReturnsFixedRefusalWithoutKnowledge`、`service.TestRAGAnswerServiceRefusesBelowThresholdWithoutAnswerCall` |
| TC-07 | 客户越权拦截 | 仅内部文档包含答案 | 以 `customer` 直接调用 `/chat` 提问 | 不返回内部答案或内部引用，结果为拒答 | 自动化通过：`router.TestChatEnforcesKnowledgePermissionsForCustomerAndInternalRoles/customer` |
| TC-08 | 内部角色访问 | 同 TC-07 | 分别以 `service`、`admin` 提问 | 两种角色均可命中内部知识并返回内部文档引用 | 自动化通过：`router.TestChatEnforcesKnowledgePermissionsForCustomerAndInternalRoles` |
| TC-09 | 最近五轮多轮对话 | 同一 Session 已有 6 轮以上问答 | 继续发送含代词或省略的追问 | Prompt 只包含同角色最近 5 轮，顺序正确，不包含更早轮次 | 自动化通过：`router.TestChatUsesLatestFiveTurnsFromSameSessionAndRole` |
| TC-10 | 刷新续聊 | 移动端已发送至少两轮 | 记录 localStorage 中 sessionId，刷新后以同角色继续提问 | 刷新前后 sessionId 不变，后端从 SQLite 恢复上下文 | 结构检查通过：`router.TestMobileChatPersistsSessionIDInLocalStorage`；真机结果记录见“人工验收记录” |
| TC-11 | 有效订单查询 | Mock LIMS 可用 | 输入“麻烦查一下订单 ORD2026001” | 返回 `type=order`、`found=true`，卡片含订单号、状态、68% 进度和报告状态，不调用 LLM | 自动化及真实 HTTP 通过：`router.TestChatReturnsStructuredMockOrderWithoutCallingLLM` |
| TC-12 | 不存在订单 | Mock LIMS 可用 | 输入“查询订单 ORD9999999” | 返回 `found=false` 和明确未找到提示，不伪造状态、进度、报告状态 | 自动化及真实 HTTP 通过：`router.TestChatReturnsExplicitMockOrderNotFoundState` |
| TC-13 | 首次空状态与加载 | 手机打开聊天页 | 进入聊天后观察空状态；发送消息并观察等待过程 | 首次有明确引导；请求期间显示“正在查询，请稍候”，发送按钮不可重复提交 | 自动化通过：静态测试及 375×812 Playwright 延迟请求检查 |
| TC-14 | 失败提示与重试 | 后端停止或网络临时断开 | 发送消息，恢复网络后点“重新发送” | 显示可理解错误和 44px 重试按钮；重试中显示状态；恢复后可成功 | 自动化通过：Playwright 中止首个请求后点击重试，第二次返回未找到订单卡片 |
| TC-15 | 软键盘适配 | Android/iOS 真机 | 聚焦输入框、输入多行文字、发送并收起键盘 | 输入框和发送按钮始终可操作，最新消息不被永久遮挡，收起后高度恢复 | 待真机：记录见“人工验收记录” |
| TC-16 | 375～430px 移动布局 | 手机或等效视口 | 检查聊天、引用、订单卡片和快捷语 | 无横向滚动；主要触控控件不小于 44px；订单字段完整 | 自动化通过：375×812 下 viewport/document/app 宽度均为 375，订单字段完整；待真机抽查 |
| TC-17 | 对话日志持久化 | SQLite 可写 | 完成知识回答、拒答和订单查询后重启连接并读取日志 | 三种回答在 HTTP 200 前落库，字段完整，拒答/订单引用为空 | 自动化通过：`repository.TestSQLiteConversationLogRepositoryPersistsCompletedTurns`、`PersistsOrderAnswer` |
| TC-18 | 文档删除、重试和重新向量化 | 已有成功及失败文档 | 对失败文档重试，对成功文档重新向量化并删除 | 重试成功清空错误；重新向量化事务替换；删除同时移除文件、元数据和分块 | 自动化通过：`router.TestFailedDocumentCanBeRetried`、`TestDocumentCanBeRevectorizedAndDeleted` |
